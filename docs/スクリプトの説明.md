# スクリプトの説明（スクリプトをいじる人・Claude は最初に読む）

最終更新: 2026-10-19 / 書いた人: プログラマー（の Claude）

ゲームの中身はほぼ全部 `Assets/Script/Game/TwoPlayerShop2D` という **1つのスクリプト** に入っている。
長くなったので、`partial class`（1つのクラスを複数のファイルに分けて書く C# の書き方）で 11 個のファイルに分けている。
Unity からは 1 つの部品に見える。シーン `SampleScene` の 1 つのオブジェクトに、`DisplayTestSwitcher` と一緒に付いている。

---

## 1. 守ること（ここだけは必ず）

1. **Inspector に出す設定（`public` の欄）は、本体 `TwoPlayerShop2D.cs` にだけ書く**
   - 別のファイルに書くと、Inspector の欄の並び順が変わってしまう
   - ON/OFF のチェックは、いちばん上の「機能のON/OFF」にまとめる
2. **袋・机・商品・カーソル・文字の大きさや、棚の縦/横は、`portraitLayout` / `landscapeLayout` で決める**
   - `bagWidthRatio`・`productSize`・`shopOrientation`・`fillPlayerScreen` などは `[HideInInspector]` で隠してあり、
     `TwoPlayerShop2D.Monitor.cs` の `ApplyMonitorMode()` が **毎フレーム上書きする**。直接いじっても戻る
   - 新しく「縦と横で変えたい値」を足すときは、`LayoutProfile`（`Monitor.cs`）に欄を足し、`ApplyMonitorMode()` で入れる
3. **新しいファイルを作ったら `.meta` も一緒にコミットする**（無いと、開いた人の Unity が別の番号で作ってしまう）
   - 中身は `fileFormatVersion: 2` と `guid: <32桁のランダムな16進数>` の 2 行でよい
4. **シーン（`.unity`）はコードからは作らない・書き換えない**。物は全部、再生したときにコードで作る（次の項目）
5. **初期値を変えても、シーンに保存済みの欄は変わらない**
   - Unity はシーンに保存された値を優先する。初期値を変えたら「Inspector の値も変えて」と人に伝える
6. Unity の版は 6000.4.0f1 のまま上げない。描画は URP

## 2. 全体の仕組み

### 画面とレイヤー
| 画面 | ディスプレイ | 映すレイヤー | 中身 |
|---|---|---|---|
| 画面1 | Display 1 | 8（`layerP1`） | 1P のレジ袋の画面 |
| 画面2 | Display 2 | 9（`layerShop`） | 商品棚 |
| 画面3 | Display 3 | 10（`layerP2`） | 2P のレジ袋の画面 |

- 3 つの画面は **同じワールド座標** を使っていて、**レイヤーで見せ分け・当たり分け** している（`ApplyScreenAssignment`（`.Screens.cs`）/ `SetupPhysicsLayers`）
- 物を作るときは、出したい画面のレイヤーにする（`go.layer = p.layer` など）。間違えると映らない・ぶつからない
- 画面とカメラの割り当て・テスト用の 1 画面表示は `DisplayTestSwitcher.cs`（`Test Mode`・F1・F2）
- インスペクターの `Screen P1 / Screen Shop / Screen P2` は **画面の番号（0, 1, 2）**。レイヤー番号ではない
  - 入れ替えてよい（再生中でもすぐ反映）。棚をメインディスプレイに出したいときは `Screen Shop` を 0 にする（2026-10-20〜 1P=1・棚=0・2P=2）
  - 背景の色は番号ではなく役割について回る（`P1/Shop/P2 Back Color`）
  - **画面の番号で処理を分けない**。カメラが要るときは `switcher.screens[p.screen]` / `switcher.screens[screenShop]` を使う

### 物は全部コードで作る
商品・カーソル・床・壁・レジ袋・ゲージ・文字・足は、再生を始めたときにコードが作る（シーンには置いていない）。
四角・丸・三角などの絵も `Sprites.cs` でその場で作る。画像を入れる欄（`Product Sprites`・`Bag Sprite`・カーソル・`Kick Foot Sprite`）に画像を入れると、そちらを使う。

### 1 フレームの流れ
- `Start()`（本体）: モニターの置き方を反映 → 物理レイヤー → 商品 → カメラ → プレイヤー → 床・袋
- `Update()`（本体）:
  1. `ApplyMonitorMode()`（配置を反映）→ `ApplyPlayerLayout()`（割合から床・袋の位置を計算）→ 床・袋を動かす
  2. タイムアップなら `UpdateResult()` だけして終わり（最初に袋を持ち上げる `UpdateBagLift()`（`.Lift.cs`）→ 結果発表）
  3. 袋に入ったか・場外か（`CheckBag`）
  4. コントローラーの割り当て（`TryAssignPads`）
  5. 掴み合い中なら `UpdateClash()` だけして終わり
  6. カーソル移動 → キック（LB）→ A（掴む/離す/キックの威力）→ RB（回す）→ キックの更新
- `LateUpdate()`（`ShopView.cs`）: 棚の設定（段・列・見た目）が変わったら作り直す（`UpdateShelfIfChanged`）→ 1P/2P のカメラのズームと回転 → 棚の並べ直し → タイマー → 棚のカメラ
  - `DisplayTestSwitcher` が `Update` でカメラを決めたあとに、こちらが上書きする順番になっている

### 大きさと位置の決め方（ここが一番大事）
- 1P/2P の画面は「**必ず映す範囲**」`PlayerViewSize()` を基準にする（横幅 `playerViewWidth`、縦は画面の形から）
  - カメラはこの範囲が全部入るように自動でズームする（`FitPlayerCameras`）
  - 床・袋・落とす高さは **範囲に対する割合** で置く（`ApplyPlayerLayout`）
  - なので、物の位置を **数字で直接書かない**。`PlayerViewSize()` や `floorY`・`wallX`・`bagX` などを使う
  - `wallX` は画面に見えている机の端（カーソル・袋はこの中）。本当の机と見えない壁は `DeskOuterX`（`wallX × Desk Extend`）で、画面の外まで続く
- 棚の画面は `ShopViewSize()`（横 17.8x10 / 縦は `portraitViewWidth` から）。棚の並びは `ShelfArea()`（棚を置く範囲）と `ShelfSlotPosition()`（`.Shelf.cs`）。商品の数 = 段 x 列（縦 `Portrait Columns/Rows`・横 `Landscape Columns/Rows`）。形・色・画像・金額の欄が足りないときは最初から繰り返す
  - 棚を出すとき（`Show Shelf`）、商品は `PutOnShelf` で **一番下を板の上の面に合わせる**。棚の商品を動かすときは `transform.position = slot.pos` ではなく `PutOnShelf` を使う
- 縦 10・横 17.8 の横幅だと、FullHD で 1 マスが同じピクセル数になり、商品・手・文字の見た目の大きさがそろう

## 4. よくある作業のしかた

### 新しい機能を足す
1. 新しいファイル `TwoPlayerShop2D.〇〇.cs` を作る（中は `public partial class TwoPlayerShop2D { ... }`）。`.meta` も作る
2. 設定の欄は本体 `TwoPlayerShop2D.cs` に足す（ON/OFF は「機能のON/OFF」へ）
3. 毎フレームの処理は、本体の `Update()`（入力・ゲームの動き）か `ShopView.cs` の `LateUpdate()`（カメラ・表示）から呼ぶ
4. 物を作るときは、出す画面のレイヤーと `sortingOrder`（手前/奥）を決める
5. 本体の先頭のコメント（ファイルの分け方）と、このファイルの表に 1 行足す

### 文字を出す
`MakeText(名前, 親, レイヤー, 文字, 色, 手前の順番)` を使う（`Bag.cs`）。日本語も出る。
大きさは **`SetTextSize(文字, 大きさ)`** で決める（`characterSize` に直接入れない。文字の解像度 `Text Resolution` を変えても見た目の大きさが変わらないように、元の絵の大きさで割って入れている）。金額などは `HudTextSize`（`Text Scale` で変わる）を使う。
フォントは Inspector の `Text Font`（空なら Unity の標準フォント）。再生を始めたときに `ApplyTextFont` で決まる。

### 手前/奥の順番（`sortingOrder` のめやす）
| 物 | 数字 |
|---|---|
| 床 | -10、袋の背景 -20 |
| 落とした商品 | 1〜（落とした順） |
| 袋のふち | 500 |
| 持っている商品 | 999、カーソル 1000 |
| 合計金額・キックの文字・足 | 1001〜1500 |
| 掴み合い・キックのゲージ | 2000〜2010 |
| 勝ち負けの表示 | 3000〜 |

### エフェクト（パーティクル）を足すとき
まだ作っていない。作るなら: ビジュアル担当がプレハブを作る → 本体に「エフェクトの欄」を足す → 決まったタイミングで `Instantiate` して、
出す画面のレイヤーにする（子も全部 `SetLayer`）。Renderer の Order in Layer を大きめに、マテリアルは URP のパーティクル用。

## 5. はまりやすいところ

- **棚の画面に何も映らない** → `Screen Shop` が 1 以外になっていないか（2026-10-19 に 8 になっていたことがある）
- **新しい欄の値が変わらない** → シーンに保存された値が使われている。Inspector で直す
- **配置の値をいじっても戻る** → `portraitLayout` / `landscapeLayout` の中をいじる（隠れている欄は毎フレーム上書き）
- **画面が横向き・逆さ** → `Monitor Mode` と回転の設定（`P1/P2 Screen Rotation`・`Shop Screen Rotation`）。横型モニターのときは回転しない
- **縦の棚で左右に古い映像が残る** → `ShopBackCamera`（`ApplyShopBackCamera`）が黒で塗っている。消さない
- **商品が袋のふちをすり抜ける** → 落とした商品は `CollisionDetectionMode2D.Continuous`。袋は Kinematic の Rigidbody2D を `MovePosition` で揺らしている
- **Claude は Unity を動かせない** → 直したら「Unity で何を確かめるか」を必ず人に伝える。コンパイルエラーが出たら、エラー文を貼ってもらって直す
