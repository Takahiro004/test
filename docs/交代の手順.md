# 交代の手順（プログラマー・リーダー向け）

2人とも Claude Code を使って、**交代しながら**作る。上限はアカウントごとなので、片方の上限が来たら、もう片方が続きをやる。
Claude どうしは会話をつなげられない。**GitHub のリポジトリが共有のノート**で、どちらの Claude もそこを直接読む。

| | プログラマー | リーダー |
|---|---|---|
| 使う Claude Code | 自分の PC（Unity プロジェクトのフォルダで起動） | Web（claude.ai/code で `Takahiro004/test` を選ぶ） |
| 変更の入り方 | main にそのまま push | `claude/` ブランチ → プルリクエスト → **Merge を押す** |

---

## 1. 始めるとき

1. **Unity でシーンを保存する（Ctrl + S）**
2. Claude Code に **「始める」** と言う
   - Claude が最新を取り込み（pull）、`docs/引き継ぎ.md` を読んで、今の状態と次にやることを教えてくれる
3. Unity に戻って「シーンが変更されました」と出たら **Reload** を押す

## 2. 作業中

- Claude にやりたいことを頼む（例: 「袋に入った商品を数えるようにして」）
- **Claude は Unity を動かせない。** 書いてもらったら、Unity で再生して確かめる。
  動かなければ、Console の赤いエラーをそのまま Claude に貼る
- 動いたら「commit して push して」と言う（こまめに。push していないものは相手に見えない）

## 3. 終えるとき

1. **Unity でシーンを保存する（Ctrl + S）**
2. Claude Code に **「終わる」** と言う
   - Claude が `docs/引き継ぎ.md` を書き直して、commit → push する
   - リーダー側は、Claude が出したプルリクエストのリンクを開いて **Merge** を押す（押さないと相手に届かない）
3. 相手に「終わった」と一言送る

## 4. 急に上限が来たとき

1. GitHub Desktop で commit → push する（途中で動かなくても OK）
2. 相手に一言送る

   > 上限きた。〇〇.cs の△△をしてた。□□がまだ動かない。次は××をやる予定。

3. 相手は自分の Claude Code に「始める。相手からの一言:『（一言）』」と言って続ける

---

## 守ること（これだけは）

- **同時に作業しない。** 相手から「終わった」が来てから始める
- **始める前に「始める」、終わったら「終わる」**（pull と push は Claude がやる）
- **同じシーン（`.unity`）を2人で同時にいじらない**
- パスワード・API キーなどの秘密情報は、リポジトリに入れない（push すると消しても履歴に残る）

## 困ったとき

- pull したら「衝突（conflict）」と出た → 自分で片方を消さず、Claude に「衝突した。どうすればいい？」と聞く
- 何をすればいいか分からない → この手順を開いて、1 から順にやる
