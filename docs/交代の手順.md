# 交代の手順（プログラマー・リーダー向け）

2人とも Claude Code を使って、**交代しながら**作る。上限はアカウントごとなので、片方の上限が来たら、もう片方が続きをやる。
Claude どうしは会話をつなげられない。**GitHub のリポジトリが共有のノート**で、どちらの Claude もそこを直接読む。

**2人ともブラウザで [claude.ai/code](https://claude.ai/code) を開き、リポジトリに `Takahiro004/test` を選んで使う。**
インストールは要らない（学校の PC でも使える）。

Claude が書いたものは、次の流れで Unity に届く。

1. Claude がプルリクエストを出す（リンクが出なければ「プルリクエストを作って」と言う）
2. リンクを開いて **Merge** を押す
3. GitHub Desktop で **Fetch origin → Pull origin** を押す
4. Unity に戻って（「シーンが変更されました」と出たら **Reload**）、再生して確かめる

---

## 1. 始めるとき

1. **Unity でシーンを保存する（Ctrl + S）**
2. GitHub Desktop で **Fetch origin → Pull origin** を押す（相手の変更を学校の PC に持ってくる）
3. Unity に戻って「シーンが変更されました」と出たら **Reload** を押す
4. claude.ai/code で新しく始めて、**「始める」** と言う
   - 最初に「リーダーですか、プログラマーですか」と聞かれるので答える
   - Claude が `docs/引き継ぎ.md` を読んで、今の状態と次にやることを教えてくれる

## 2. 作業中

- Claude にやりたいことを頼む（例: 「袋に入った商品を数えるようにして」）
- Claude がプルリクエストを出したら、**Merge → Pull → Unity で再生**して確かめる
- **Claude は Unity を動かせない。** 動かなければ、Console の赤いエラーや「こう動いてほしいのにこうなった」をそのまま Claude に送る。
  直したら、また新しいプルリクエストが出るので、Merge → Pull をやり直す
- Unity の画面でシーンをいじったとき（オブジェクトの配置など）は、自分で GitHub Desktop から commit → push する

## 3. 終えるとき

1. Unity でシーンをいじっていたら、保存（Ctrl + S）して GitHub Desktop で commit → push する
2. Claude に **「終わる」** と言う
   - Claude が `docs/引き継ぎ.md` を書き直して、プルリクエストを出す
3. リンクを開いて **Merge** を押す（押さないと相手に届かない）
4. 相手に「終わった」と一言送る

## 4. 急に上限が来たとき

1. GitHub Desktop で commit → push する（途中で動かなくても OK）
2. 相手に一言送る

   > 上限きた。〇〇.cs の△△をしてた。□□がまだ動かない。次は××をやる予定。

3. 相手は自分の Claude に「始める。相手からの一言:『（一言）』」と言って続ける
   （Claude が途中まで書いてプルリクエストを出していなければ、その分は相手に届かない。一言に「どこまで Merge したか」も書く）

---

## 守ること（これだけは）

- **同時に作業しない。** 相手から「終わった」が来てから始める
- **始める前に Pull して「始める」、終わったら「終わる」→ Merge**
- **同じシーン（`.unity`）を2人で同時にいじらない**
- パスワード・API キーなどの秘密情報は、リポジトリに入れない（push すると消しても履歴に残る）

## 困ったとき

- pull したら「衝突（conflict）」と出た → 自分で片方を消さず、Claude に「衝突した。どうすればいい？」と聞く
- 何をすればいいか分からない → この手順を開いて、1 から順にやる
