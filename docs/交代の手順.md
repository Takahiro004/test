# 交代の手順（プログラマー向け）

チャットの上限が来ても作業が止まらないように、**プログラマーのチャット**と**リーダーの Claude Code** で交代しながら進める。
そのための手順。

## なぜこうするのか
- Claude どうしは会話をつなげられない。**GitHub のリポジトリが共有のノート**になる
- リーダーの Claude Code はリポジトリを直接読めるので、push されたコードとメモ（`docs/引き継ぎ.md`）を読めば続きからできる
- チャット（claude.ai）はリポジトリを読めないので、**必要なファイルを自分で渡す**
- チャットは前の会話の古いコードを覚えている。そのまま続けると、**リーダー側で足したコードを古いコードで上書きして消してしまう**。
  だから戻るときは新しいチャットで、最新のファイルを渡して始める

---

## 1. 作業を始めるとき

1. **Unity で作業する前に、GitHub から最新を取り込む（pull）**
   - いつも push に使っている方法（GitHub Desktop など）で pull する
   - これを忘れると、リーダー側の変更と食い違って衝突する
2. **`docs/引き継ぎ.md` を開いて読む**（GitHub の画面か、プロジェクトのフォルダの中）
   - 「変えたファイル」: リーダー側が変えたファイル
   - 「チャットに渡すファイル」: 次にチャットへ渡すファイル
3. **新しいチャットを開く**（前のチャットの続きにしない）
4. **ファイルを渡す**: `CLAUDE.md`、`docs/引き継ぎ.md`、「チャットに渡すファイル」に書かれたファイル
   - チャットの「＋」→「GitHub から追加」があれば、そこからリポジトリのファイルを選ぶ
   - 無ければ、プロジェクトのフォルダからそのファイルをアップロードする
5. **最初にこう送る**

   > これはチームで作っている Unity のゲームのファイル。CLAUDE.md と docs/引き継ぎ.md を読んで、今の状態と次にやることを短く教えて。
   > コードを書き直すときは、ここで渡したファイルが最新なので、これを元にして。

---

## 2. 作業中

- チャットに書いてもらったコードを Unity に貼って、動くか確かめる
- **動いたら、こまめに commit → push する**（push していないものは、リーダーの Claude に見えない）
- commit のメッセージには、何をしたかを書く（例: 「袋に入った商品を数えるようにした」）。これも引き継ぎになる
- 新しいファイルを作ったら、Unity が作る `.meta` ファイルも一緒に commit する

---

## 3. 作業を終えるとき（または「残りわずか」の警告が出たとき）

上限が来るとチャットに何も頼めなくなる。**警告が出たら、先にメモを書かせる。**

1. チャットにこう送る

   > ここまでの作業を元に docs/引き継ぎ.md を書き直して。「今の状態」「次にやること」「変えたファイル」「チャットに渡すファイル」「止めたところ・注意」の見出しはそのままにして、ファイル全体を出して。

2. 出てきた中身で、プロジェクトのフォルダの `docs/引き継ぎ.md` を上書き保存する
3. コードと一緒に commit → push する

---

## 4. 急に上限が来たとき

メモを書かせられなかった場合。

1. 今のコードを commit → push する（途中で動かなくても OK。止めるのは「パスワードなどの秘密情報」と「50MB を超える巨大ファイル」だけ）
2. **リーダーに一言送る**

   > 上限きた。〇〇.cs の△△をしてた。□□がまだ動かない。次は××をやる予定。

   この一言を元に、リーダーの Claude が続きをやる

---

## 5. 戻るとき（上限が解けたら）

1. **リーダーから「続きやっといた」と連絡が来ているか確かめる**
   - 来ていなければ、リーダーの作業中かもしれない。**同時に作業しない**ので、終わるまで待つ
2. **「1. 作業を始めるとき」と同じ手順で始める**（最新を取り込む → 引き継ぎ.md を読む → 新しいチャットにファイルを渡す）
3. どうしても前のチャットで続けたいときは、最新のファイルを渡してこう添える

   > 上限の間に別の Claude が作業した。これが最新なので、前の会話のコードは古いものとして扱って。

---

## 守ること（これだけは）

- **同時に作業しない。** 片方が push し終えてから、もう片方が始める
- **始める前に pull、終わったら push**
- **戻るときは新しいチャットで、最新のファイルを渡す**
- **同じシーン（`.unity`）を2人で同時にいじらない**
- パスワード・API キーなどの秘密情報は、リポジトリに入れない（push すると消しても履歴に残る）

## 困ったとき

- pull したら「衝突（conflict）」と出た → 自分で片方を消さず、リーダーに連絡する。リーダーの Claude で直す
- 何をすればいいか分からない → この手順を開いて、1 から順にやる
